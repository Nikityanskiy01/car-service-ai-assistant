# Release Readiness

Документ фиксирует, как собрать воспроизводимый финальный снимок проекта перед релизом.

## 1) Проверки перед упаковкой

Минимум (локально):

```bash
cd backend
npm ci
npm run lint
npm test
```

```bash
# из корня
npm ci
npm run test:e2e
```

Если Docker daemon недоступен, тесты с БД и E2E будут падать по инфраструктуре.

## 2) Рекомендуемая структура финальных коммитов

1. `docs`: синхронизация документации и чек-листов.
2. `ci`: правки пайплайна (если есть).

Такой порядок упрощает ревью и откат несвязанных изменений.

## 3) Политика по бинарным артефактам

В git **не** храним: `Sample/`, Proxmox tmp-секреты, локальные дампы БД с персональными данными.

Оставляем: markdown в `docs/`, исходный код приложения, конфигурацию CI.

## 4) Команды для финальной сборки снимка

```bash
git status --short
git add README.md docs/testing.md docs/demo-defense.md docs/release-readiness.md
git add .github/workflows/ci.yml .gitignore specs/001-ai-consultation-platform/tasks.md
git add docs
git status
```

После этого проверить, что в staged попало только ожидаемое, и сделать финальные коммиты по блокам из п.2.

## 5) Definition of Done для релиза

- инструкции из `README.md` выполняются на чистом окружении;
- демо-сценарий из `docs/demo-defense.md` проходит без импровизации;
- тестовые/CI-команды воспроизводимы;
- состав артефактов (`docs`) формально зафиксирован.
