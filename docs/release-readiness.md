# Release Readiness (сдача ВКР)

Документ фиксирует, как собрать воспроизводимый финальный снимок проекта перед сдачей.

## 1) Проверки перед упаковкой

Минимум (локально):

```bash
cd backend
npm ci
npm run lint
npm test
```

```bash
# из корня
npm ci
npm run test:e2e
```

Если Docker daemon недоступен, тесты с БД и E2E будут падать по инфраструктуре.

## 2) Рекомендуемая структура финальных коммитов

1. `docs`: синхронизация документации и чек-листов защиты.
2. `ci`: правки пайплайна (если есть).
3. `thesis-assets`: материалы ВКР (pdf/pptx/docx/изображения), если их нужно хранить в репозитории.

Такой порядок упрощает ревью и откат несвязанных изменений.

## 3) Политика по бинарным артефактам

Перед финальным коммитом явно выбрать один из вариантов:

- оставить в репозитории: `docs/*.pdf`, `docs/*.docx`, `docs/*.pptx`, `thesis/main.pdf`, `thesis/images/media/*`;
- или исключить через `.gitignore` и хранить в отдельном архиве сдачи.

Нужно выбрать один подход и придерживаться его для воспроизводимости.

## 4) Команды для финальной сборки снимка

```bash
git status --short
git add README.md docs/testing.md docs/demo-defense.md docs/release-readiness.md
git add .github/workflows/ci.yml .gitignore specs/001-ai-consultation-platform/tasks.md
# опционально: материалы ВКР
git add docs thesis
git status
```

После этого проверить, что в staged попало только ожидаемое, и сделать финальные коммиты по блокам из п.2.

## 5) Definition of Done для сдачи

- инструкции из `README.md` выполняются на чистом окружении;
- демо-сценарий из `docs/demo-defense.md` проходит без импровизации;
- тестовые/CI-команды воспроизводимы;
- состав артефактов (`docs`, `thesis`) формально зафиксирован.
