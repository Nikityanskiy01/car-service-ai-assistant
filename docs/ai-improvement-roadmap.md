## Как устроено сейчас (кратко)

Три «роли» в одном пайплайне:

| Роль | Что делает | Нейросеть? |
|------|------------|------------|
| **Регистратор** | Задаёт вопросы по шаблону (марка → модель → симптомы → условия) | Нет |
| **Секретарь** | Извлекает поля из текста клиента в JSON | Иногда |
| **Мастер** | Формирует причины, проверки, срочность, цену «от» | Да |

Нейросеть вызывается **только дважды** (извлечение + диагноз), ответ — строгий JSON. При сбое — rule-based fallback, сессия не падает.

**Ключевые файлы:**

- `backend/src/services/ollamaService.js` — HTTP к Ollama / OpenAI-compatible API
- `backend/src/services/consultationFlowService.js` — диалог и extraction
- `backend/src/modules/consultations/consultationAi.service.js` — диагноз и merge
- `backend/src/prompts/consultationPrompts.js` — промпты и JSON-схемы
- `backend/src/services/caseMemory.service.js` — «память» кейсов (лексический поиск)

---

## Цель: «супер-решение»

Не ChatGPT-обёртка, а **умный приёмщик автосервиса**:

- Клиент понимает, что происходит, и быстро получает полезный результат
- Менеджер видит готовую карточку кейса, может поправить и улучшить систему
- Бизнес получает больше заявок и измеримое качество ИИ

**Принцип:** не выкидывать гибрид (правила + LLM), а усилить его.

## Метрики успеха

| Метрика | Baseline | Цель |
|---------|----------|------|
| p95 время до уточняющего вопроса | ~1–5 с | ≤ 3 с |
| p95 время финального диагноза | до 240 с (таймаут) | ≤ 45 с |
| Доля fallback без LLM | не измеряется | < 5% |
| Менеджер: «диагноз полезен» | нет данных | ≥ 70% |
| Конверсия консультация → заявка | нет в аналитике | +15–20% |

## Фаза 1 — Умная память (2–4 недели)

**Цель:** похожие кейсы находятся по смыслу, а не только по словам.

**Статус:** реализовано (JSON embeddings + cosine; pgvector — опционально позже)

### Семантический поиск (лёгкий RAG)

- [x] Выбрать embedding-модель: `LLM_EMBEDDING_MODEL=nomic-embed-text` (Ollama) / `text-embedding-3-small` (OpenAI)
- [x] Таблица `consultation_case_embeddings` (JSON float[], Prisma migration)
- [x] Индексировать: симптомы + категория + марка + итоговые работы
- [x] Гибрид в `caseMemory.service.js`: semantic + lexical fallback
- [x] В промпт — топ-5 похожих анонимизированных кейсов (`CASE_MEMORY_TOP_K=5`)
- [x] Бэкфилл: `npm run case-memory:backfill` (+ авто-индекс при завершении консультации)

### Качество

- [x] Unit-тест: «стук» / «стучит» ближе друг к другу, чем к «двигатель троит» (pseudo-embedding)
- [ ] Сравнить lexical vs semantic на 10–20 реальных кейсах после бэкфилла с Ollama

**Критерий готовности фазы:** на тестовых парах («стук» / «стучит») semantic находит тот же кейс стабильнее lexical.

### Запуск

```bash
# 1. Миграция
cd backend && npm run prisma:migrate

# 2. Скачать embedding-модель в Ollama
ollama pull nomic-embed-text

# 3. Проиндексировать завершённые сессии
npm run case-memory:backfill
```

## Фаза 4 — Инженерная зрелость (параллельно / после MVP+)

**Цель:** выдержать нагрузку и не ломать качество при изменениях (спека: 50 консультаций, 99% uptime).

**Статус:** частично реализовано (eval + resilience + BullMQ async; A/B промптов — опционально)

### Инфраструктура

- [x] Очередь на диагноз — BullMQ + Redis (`DIAGNOSIS_ASYNC_ENABLED`, `REDIS_URL`) + in-memory fallback
- [x] Кэш похожих запросов (hash: симптомы + марка + модель)
- [x] Circuit breaker при повторных сбоях LLM

### Качество и наблюдаемость

- [x] Eval-набор 38 сценариев в `backend/tests/eval/`
- [x] CI: job `eval-prompts` + `npm run test:eval`
- [x] Метрики: latency, fallback rate, validation failures (админка → карточка ИИ)
- [ ] (Опционально) A/B промптов через флаг в админке

**Критерий готовности фазы:** любое изменение `consultationPrompts.js` проходит eval без регрессии.

## Что НЕ делать

| Идея | Почему |
|------|--------|
| Fine-tune свою модель | Дорого, долго, избыточно для MVP |
| Полностью отдать диалог ChatGPT | Потеря контроля и безопасности |
| LangChain «на всякий случай» | Текущий тонкий `fetch` проще |
| Свободный чат на любые темы | Галлюцинации, размытие продукта |
| Всё фазы сразу | Лучше 0 → 1 → 2, потом wow |

## Рекомендуемый порядок работ

```
Фаза 0 (UX + скорость + fallback)
    ↓
Фаза 1 (семантическая память)  ←── параллельно можно начать eval из Фазы 4
    ↓
Фаза 2 (feedback менеджеров)
    ↓
Фаза 3 (OBD / интерактив / фото — по приоритету)
    ↓
Фаза 4 (очередь, метрики, CI eval)
```

**Минимум «круто к демо»:** Фаза 0 + кусок Фазы 1 (pgvector на seed-кейсах) + одна фича из Фазы 3.

## Ключевое позиционирование

> Система — не чат-бот, а **гибридный интеллектуальный приёмщик**: детерминированный сценарий сбора данных, семантическая память прошлых кейсов сервиса, LLM для структурированного диагноза и замкнутый контур обратной связи от мастеров — с гарантированным fallback при недоступности модели.
